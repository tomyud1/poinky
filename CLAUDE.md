# Poinky

A macOS menu bar app: hold ⌃⌥ and talk to Claude about what's on your screen (or ⌃⌥Space for a hands-free call), and it answers out loud while marking the screen and sketching explanations on a "paper" with a yellow pen (2D lessons) or narrated 3D models. Inspired by the HeyClicky "real-time graphics" demo.

## Where it's going (read docs/VISION.md before agent or UI work)
Poinky is meant to become the main way people use Claude Code: agents that live on the screen instead of in their own window. The main agent (the buddy at your cursor) answers instantly and hands longer work to **helpers**: smaller colored cursors that bud off the main cursor, take a task, work at the edge of the screen while showing short progress lines, then celebrate, fly back, and the main agent speaks their summary. Each helper is a real Claude Code session (`AgentManager`), so it must stay as capable as the terminal; users care about progress and summaries more than diffs. The design bar is Apple-level motion and sound (springs, one shared timing family, sounds in one key and panned to where they come from, Reduced Motion, color plus a second cue). The phased plan, with tests for each phase, is in `docs/VISION.md`. The main agent never does long work itself.

## Build & run
- `./build.sh` builds `build/Poinky.app` (Swift Package, macOS 26+, no Xcode project). Then `open build/Poinky.app`.
- Restart after a rebuild: `pkill -f "Poinky.app/Contents/MacOS/Poinky"; open build/Poinky.app`. **Ask the user before restarting** if they might be mid-call.
- Signing: `build.sh` signs with your Apple Development cert if present, else the local "Poinky Local Signing" certificate (login keychain; created by `build.sh` on first run via `/usr/bin/openssl` + `security import`; the old "ScreenBuddy Local Signing" is still honored) so macOS keeps Microphone / Screen Recording / Accessibility permissions across rebuilds. Ad-hoc signing would reset them every build. `POINKY_KEYCHAIN=/path` signs/creates in another keychain (for testing); `POINKY_ADHOC=1` skips certificates (CI). Signing has a timeout (`POINKY_SIGN_TIMEOUT`, 120 s) and falls back to ad hoc, because on a headless Mac `codesign` with a new keychain key waits forever for a "allow access" dialog.
- Installer: `install.sh` (curl | bash; also `--no-voice`, `--uninstall [--purge]`) checks macOS/CLT/SDK ≥ 26, offers Claude Code, clones to `~/Library/Application Support/Poinky/source`, runs `build.sh` (log in `install.log`), runs `phonon/install.sh`, copies the app to /Applications.
- Local voice: Phonon 31m (Gradium, Apache 2.0; replaced Kokoro). `phonon/install.sh` installs it into `~/Library/Application Support/Poinky/phonon` (installs `uv` into `Poinky/bin` if missing; uv-managed Python only (`--python-preference only-managed`); pinned `ptts==0.6.0`; model + 25 catalog voices from Hugging Face at pinned revisions, each file verified by SHA-256; ends by making the helper speak; writes `installed.json`; removes the old `Poinky/kokoro`). `POINKY_PROGRESS=1` adds `@progress <0-1> <step>` lines, which `PhononInstaller` (Settings → Voice → Install, and automatic when `Poinky/kokoro` exists) shows. Test it as a new user with `env -i HOME=/tmp/x PATH=/usr/bin:/bin:/usr/sbin:/sbin bash phonon/install.sh`.
- Settings: `~/Library/Application Support/Poinky/config.json` (also editable from the Settings window).

## Architecture (Sources/Poinky)
- `CallController` runs a session in one of two modes: hold-to-talk (`PushToTalk` polls the modifier keys; the mic opens only while held; release → `SpeechListener.finishUtterance()`) or a hands-free call (mic always on, silence ends a question). The loop: listen → screenshot → **talker** (fast model, short spoken answer + quick screen marks) and **teacher** (stronger model, narrated `<lesson>` sketches or `<scene3d>` models) → speak + draw. Handles interrupts, follow-ups, placement, window anchoring.
- `Brain` protocol: `ClaudeCodeBrain` (persistent `claude -p` stream-json session, uses the subscription) and `APIBrain` (Messages API). Parsers: `TalkParser` (`<say>/<visual>/<draw>`), `ArtistStream` (`<lesson>/<say>/<step>/<step3d>/<scene3d>`).
- Audio: `AudioIO` (one AVAudioEngine; voice processing for echo cancellation), `SpeechListener` (SpeechAnalyzer; ends on real silence via `VoiceActivity`), `Speaker` (sentence queue, tagged lines so drawing steps start with their sentence; a lesson line isn't queued behind the one before it until that one is heard, and a 3D step calls `holdNext` (`CallController.stepDwell` 2.2 s from the step, `stepBreath` 0.4 s after its sentence) so the next sentence waits at the gate; Phonon audio is streamed chunk by chunk after a 0.1 s safety buffer, and a 10 ms silent buffer closes each sentence: it flushes the resampler and moves the captions on), `PhononVoice` (`phonon_server.py` over stdin/stdout: `{"id","text","voice","speed"}` in, `{"id","bytes"}`+float32 chunks then `{"id","end"}` out, `{"cancel": id}` drops everything up to that id mid-sentence; CPU q8_0 weights on performance cores (max 4 threads, faster than also using efficiency cores), QoS userInteractive; speed is a multiplier mapped onto Phonon's `duration_delta` (reliable only 0.86–1.24×); `SilenceTrimmer` cuts the ~120 ms of silence before and ~600 ms after every sentence, with a threshold set from each sentence's own noise floor, since some voices have room tone near -65 dB and a soft "f" is near -55 dB).
- Home: `NotchHome` (SwiftUI in a panel above the overlay, centered on the notch; idle it's exactly the notch's size so it's invisible; hover opens controls). The menu bar item is hidden unless `menuBarIcon` is on or no screen has a notch. Sounds: `Earcons` (synthesized; played through `AudioIO`'s own player node during a session).
- Screen: `ScreenCapture` (ScreenCaptureKit; image size kept ≤1568px / 1.15MP so Claude's coordinates are 1:1), `MarkSnapper` (Vision OCR lines + words; marks with `"find"`/`"to"` are placed on that text, others are nudged onto nearby words (a box that covers most of a line grows to the whole line; `InkMap` finds bullets/checkboxes OCR skips so list boxes include them); picks label spots `lx`/`ly`/`la` that cover the least text), `Placement` (paper/caption placement), `WindowTracker` (drawings follow/hide with their window).
- 3D step notes: `<step3d id note="…">` (the teacher writes 2–6 words; missing → `CallController.shortNote` of its sentence, once per sentence; a fix with no sentence adds none) → `SB.run3d(id, code, note)` adds a line to the model card's notes column (`addNote`: the card grows on the side with room, away from the photo, so the 3D view keeps its size; no room → over its left edge) and sends `{sbRun, note: i}`. The kit saves each step's camera goal when the next step starts (`saveView`) and its temp labels (`noteTemps`); clicking a note sends `{sbRevisit: i}` → `kit.revisit(i)` (camera back, temp labels again, its part labels flash); the next step first returns to the lesson's view. Test: `tools/tests/kit-notes.html`.
- Overlay: `Overlay.swift` + `web/overlay.html` (annotations, cards, captions), `web/lesson.js` (paper + pen engine), `web/buddy.js` (cursor buddy + caption bubble; sounds are native `Earcons`; it wraps `SB.caption`/`SB.apply`), `web/kit.js` (3D kit over three.js r160 in `vendor/`). Cards run in sandboxed iframes with no network.
- Talker extras (parsed in `TalkParser.finish`): `<remember>`/`<forget>` → `Memory` (memory.md, added to talker + guide system prompts), `<set>{…}</set>` → a whitelist of safe settings (`applyVoiceSettings`), `<agent title dir>task</agent>` → `AgentManager`, `<end/>` → end the session after speaking. Finished agents queue in `agentReports` (with their ids) and are spoken when you're free (`deliverReports`: not while holding the keys or Claude talks, not within 2 s of a key press (`secondsSinceTyping`), not while the screen is locked (`screenLocked`); idle starts a quiet session) or added to the next question. `startReporting` sends `SB.helperReport` (the helpers fly to the buddy) and marks them heard in the notch; `releaseReports` (`SB.helperRelease`, they merge) runs when the speech ends, a new question starts, or the session ends. `NotchModel.reports` keeps the last 12 (dots for unheard ones, the last three in the hover panel).
- Looking things up (`Recall.swift`, `WebSearcher.swift`): the talker's `<recall>words</recall>` and `<search>query</search>`. `CallController.ask` speaks the short line, runs `lookUp` (recall: `Recall.find` over `ConversationLog` + `PastHelper.list` + `ClaudeSessions`, no model; search: `WebSearcher`, its own `claude -p` with `--tools WebSearch,WebFetch` + `--allowedTools` and nothing else, in `Poinky/web-search`, 30 s timeout (it says "Still looking." after 10 s; searches take ~10–20 s, WebFetch at most one page), started as soon as the reply contains `<search`), then sends the results as a text-only follow-up turn (`BrainQuestion(snapshot: nil)`). While `lookupReply` is set, `handle` keeps only `<say>/<draw>/<visual>` (`TalkEvents.onlySpeech`), so web pages and old transcripts can't start helpers, click, change settings, remember, or look up again. `ConversationLog`: `conversations/YYYY-MM-DD.jsonl` (0600; you, poinky, front app, note), written by `logExchange` (setting `conversationLog`); the first question of a session gets the last 3 exchanges if they're under 3 h old (`carriedOver`). `ClaudeSessions` reads only the last 96 KB of each `~/.claude/projects/*/*.jsonl` changed in 30 days (custom-title / ai-title / last-prompt / cwd / gitBranch), skipping Poinky's own helpers; `<agent resume="cc-…">` continues one as a helper with `--resume` + `--fork-session` in its own folder (no worktree; helper notes go in the message, since a resumed session keeps its system prompt). The talker's instructions for both are added in code (`LookUp.promptSection`), depending on the settings. `POINKY_CONVERSATION_DIR` / `POINKY_CLAUDE_PROJECTS` point them elsewhere for tests.
- Helpers (background agents, `AgentManager`): each is `claude -p --input-format stream-json` in the project folder, with a name from `AgentManager.names` (Mint, Coral, Violet, Amber, Rose, Sky; no Blue, since the main buddy is blue). Input stays open so `send(id:text:)` can add follow-ups: Claude Code folds a message that arrives mid-turn into the current turn (one result), and one that arrives after a result starts a new turn. So after each result it waits `turnGrace` (3 s) for more output before closing input; the exit then counts as finished. `HelperStream` (`HelperEvents.swift`) turns the stream into `HelperEvent`s (started, step "Reading x.py", note, checklist from TodoWrite, blocked from "requires approval" refusals, turnEnded); `onEvent` delivers them. At most `maxHelpers` (default 3) run; more are `.queued` and start when one ends. Logs: `agents/<stamp>-<title>.md` (readable) and `.jsonl` (raw stream, each line with `_t`).
- Doing things for you: the talker's `<do>task</do>` starts the guide loop in acting mode (`Guide.acting`, prompt `prompts/doer-prompt.md`, role `.doer`). Each step: screenshot → `<say>` + `<act>{"do":"click|type|key|scroll|open|wait",…}</act>` or `<ask>` / `<done>` → `Computer` (CGEvent clicks/typing, needs Accessibility) → look again. Each look also sends `AppReader`'s reading of the front app (accessibility tree: menu bar, keyboard focus + its contents, numbered buttons/fields with exact positions; Chrome/Electron get `AXManualAccessibility`); acts can target `"el":N`, and `{"do":"menu","path":"Format > Checklist"}` presses menu items via AX. Typed `\n` is a plain Return (new paragraph), Shift+Return in `Computer.chatApps` or with `"newline":"shift"`. The doer runs on `doerModel` (Sonnet by default; Haiku was too weak at multi-step app use), with a fresh session per task. Check the reading without a call: `open -n -g build/Poinky.app --args --read-app /path/out.txt ["Menu > Item"]` (runs as the signed app, so it has its Accessibility permission). Without Accessibility permission it asks macOS, shows the steps meanwhile, and takes over by itself once you allow it within 2 minutes (`watchForHands` → `takeOverGuide`). Safety in code: clicks on words like Send/Buy/Delete need a spoken yes (`riskyWords`), no typing into secure fields (`Computer.focusIsSecure`), blocked shortcuts (`Computer.blocked`), ⌃⌥ tap / Esc / talking stops it. Setting `computerControl`.
- Talking to a helper: the page reports the helper under the mouse (`{kind:'helperPointed'}` → `Overlay.pointedHelper`); `pushCommit` locks it as `talkTarget` and calls `SB.helperListen` (the card opens, its line says "Listening…"). `heard(utterance:)` sends what you said there, or a sentence about a helper by name (`HelperTalk.byName`, only clear shapes like "how's Mint doing", "tell Mint to…", "Mint, …"), to `talkToHelper` → `HelperScreen.talk(to:_:)`: `HelperTalk.intent` picks stop / status / message without a model; status is spoken from its events (`HelperTalk.status`); a message goes to `AgentManager.send` (a queued helper gets it added to its task) and `SB.helperHeard` shows "✓ Got it"; a finished helper hands the question to the talker with its summary (`helperContext`). The talker can also write `<tell agent="Mint">…</tell>` and `<stop agent="Mint"/>`.
- Raising a hand (Phase 6): helpers run with `--permission-prompt-tool stdio`, so anything not pre-approved arrives on their output as a `control_request` (`can_use_tool`) and Claude Code waits (no timeout) for a `control_response` on stdin. `HelperStream` turns it into `.asking(HelperAsk)` (`.askCancelled` for `control_cancel_request`); `HelperAsk` (no model) has the plain words (`bubble` "Can I run npm install left-pad?", `spoken`, exact `detail` for the card; risky parts are always said), `risky`, AskUserQuestion's questions (asked one at a time, `recording`), `reply(to:addressed:)` (a yes must be clear, a no can be loose, a question back is `.unclear`), and the `response`. `--settings {"permissions":{"ask":HelperAsk.askRules}}` makes pushing, deleting and installing ask even in auto mode; "yes, always" adds Claude Code's suggested rule for that session only, never for risky ones. `AgentManager` keeps `Agent.asks` and calls `onAsksChanged`; `answer(id:_:)` writes the response (a yes with "but …" also sends a follow-up). `HelperScreen.asksChanged` raises the hand (`SB.helperAsk`), one at a time on screen (`nextAsk`); when one reaches the buddy the page posts `helperAsking` → `CallController.helperAsking` → `deliverAsk` says it when you're free (same rules as reports, it may start a quiet session) → `schedulePark` sends it back to the edge after 30 s unanswered (`SB.helperPark`, "?" badge, card shows the command with Allow / Don't allow, or You choose / Skip). `heard(utterance:)` first tries `HelperScreen.askReply` (pointing at it, its name via `HelperTalk.without(name:in:)`, or the one next to the buddy) → `answerAsk`. Only your speech or a card click answers: the talker has no tag for it and `<tell>` is just a message (tested).
- In plan mode (`plan="true"` on `<agent>`, or the "plan" setting) `ExitPlanMode` is a normal request (`HelperAsk.isPlan`, card "Go ahead / Not now"): yes sends `updatedPermissions` `setMode` (auto) plus `addRules` for `safeTools`; anything else said to it is `.no(reason:)` = what to change.
- Phase 7. The Helpers window (`HelperWindows`, one window, `web/helper-window.html`): `HelperStream` also produces `HelperEntry`s (`takeEntries`), and `AgentManager.record` keeps them in `Agent.entries` and `<log>.chat.jsonl` (task, note, step, todo, ask, answer, you, end, session, checkpoint, worktree, merged, undone…). Earlier helpers come back from those files (`PastHelper.list`). Helper notes are in `--append-system-prompt` (the message is just the task, so `/review` works). Pause = `control_request` `interrupt` (the turn ends, `Agent.paused` keeps it open). Resume = `--resume <session>` with the same log and window (`AgentManager.resume`, `<agent resume="KEY">`). Undo (`HelperUndo`): helpers run with `CLAUDE_CODE_ENABLE_SDK_FILE_CHECKPOINTING` and `--replay-user-messages` (each echoed message's `uuid` is a checkpoint); undo resumes the session with no message and sends `rewind_files` (dry run first: only that lists files). Worktrees (`HelperWorktree`): a helper starting in a repo another running helper is in gets `git worktree add --detach` from `git stash create`; on finish its diff is `git apply`'d to your folder (patch kept for undo) or committed to `poinky/<name>-…`. The mouse: `askRules` include `mcp__computer-use` and `mcp__claude-in-chrome`; after one yes per helper Poinky answers those itself, one helper at a time (`handsHolder`, released after 15 s idle). `TypeBox` (⌃⌥T) and `AwayNotifier` (ntfy, opt-in, one-time code per request; `tools/fake-ntfy.py` for tests).
- Models: `AppConfig.model(for:)` / `effort(for:)` per role (talker, artist, guide (defaults to the talker's), doer); helpers use `agentModel` / `agentEffort`. Effort "" (Automatic) keeps today's fast path (Claude Code: thinking off; API: effort low, Haiku without thinking); a level passes `--effort` (or `output_config.effort`) and lets it think. Settings → Claude lists full model names (Claude Code's short names depend on its version) and checks `claude --version` (Opus 5.5 / Fable 5.1 need 2.1.280+). `Poinky --settings-shot out.png [voice]` saves a picture of that tab (or the Voice tab).
- Helpers on screen: `HelperScreen` turns `AgentManager`'s callbacks (`onStarted`, `onEvent`, `onFinished`, `onStopped`) into overlay calls; `web/helpers-app.js` runs a `HelperLayer` over the whole overlay, using `SB.buddyPos()` / `SB.buddyReact()` from buddy.js (the buddy squashes when a helper buds, turns to face it during the hand-off, hops when it merges back) and plays `Sounds` with the user's sound settings. The page reports how many helpers are on screen (`{kind:'helpers'}`); `Overlay.hide()` keeps the panel up (click-through, following the mouse) until that's 0. The talker is told the next helper's name (`agents.nextName`) so it can say "I'll have Mint fix that". `HelperScreen` also polls the front app's frontmost window twice a second while helpers are on screen (`frontWindowRect`, CGWindowList bounds, no permission needed) and sends it as `SB.helperAvoid` (Auto side), and handles card buttons (`{kind:'helperAction'}`: stop / log / folder). Open cards report their rects (`{kind:'helperRects'}`); `Overlay.trackMouse` lets clicks through only there.
- The helper drawing itself (in progress, see docs/VISION.md): `web/helpers.js` (`HelperLayer`: one hand-off at a time (others `wait` inside the main buddy), a report line on the other side, one question at a time, a push-apart so nothing overlaps; Auto side from `setAvoid`; `setPointer` fades a card you pass over and opens the card of a helper you rest on; `busy` says whether smooth frames are needed (helpers-app.js drops to 10 fps otherwise); styles are written only when they change, and the idle motions (ring sweep, bob) are CSS on their own layers because animating SVG repaints every frame. ## Hard-won gotchas
- Voice processing: create the engine's output side (`outputNode`, `mainMixerNode`) **before** `setVoiceProcessingEnabled(true)`, then connect mixer→output with the output node's format, or the engine fails with -10875. Mic channel 0 is the cleaned voice (9 channels come back).
- `@State` doesn't compile with CommandLineTools (its macro plugin is missing): keep SwiftUI view state in an `ObservableObject` (e.g. `NotchModel.hoverButton`).
- The talker may write several `<say>` blocks; `TalkParser` speaks all of them. `JSONRepair` also tries dropping a stray `}`.
- Hold-to-talk audio: playback runs in an engine that never touches `inputNode` (touching it would open the mic); the mic is a separate engine started per hold. `MicRelay` keeps audio that arrives before the speech engine is ready.
- SpeechAnalyzer: `finalize(through: nil)` settles a hold in ~0.2 s (with a time it can hang). Don't drop results by timestamp after a finalize: the final for new speech can start slightly before the press.
- Vision OCR: pin `VNRecognizeTextRequestRevision3`; the newest revision took ~30 s per screenshot on macOS 27.
- WKWebView: the overlay loads from the bundle with `loadFileURL`; three.js and the kit are passed as text (`web/libs.js`, generated by build.sh) because sandboxed frames can't load files.
- App Nap: with no session running (no audio), macOS naps Poinky and WebKit pauses the overlay's animations, so helpers froze mid-flight. `Overlay` holds a `ProcessInfo.beginActivity` while it's on screen (`keepAwake`).
- Phonon: after any pause over ~0.1 s the first chunk takes ~20 ms instead of ~5 (the CPU clocks down); a warm-up ping while the reply streams in only saved ~3 ms, so there isn't one. The first sentence after the helper starts, and the first with a new voice, are also ~15 ms slower.
- Phonon's audio chunks grow (80 ms, 80 ms, 240 ms, 480 ms…), arriving ~6 ms apart at first, so the 0.1 s buffer before playing costs a few ms and protects against main-thread stalls.
- Audio device changes (AirPods connecting or hopping between iPhone and Mac, and especially AirPods going into headset mode with a different sample rate when a mic opens) stop the AVAudioEngine with `AVAudioEngineConfigurationChange`; everything scheduled then reports "played" at once in silence. `AudioIO` rebuilds the engine (`restartIfStopped`, 0.3 s after the last change, retries while Bluetooth connects) and calls `onRestart`; `Speaker` notices the first completion from a stopped engine (`lostDevice`), keeps its place (`keepPlace`: the cut sentence and anything scheduled go back to the front of the queue) and replays from there without repeating captions or steps. Simulate it by changing the speakers' nominal sample rate (48000 → 44100) mid-sentence; a plain device switch at the same rate doesn't stop the engine.
- Never wait on a Claude reply or a system call without a way out. `ClaudeCodeBrain` answers one question at a time, so a stuck turn used to freeze every later question: `Brain.cancelCurrent()` (called on interrupt, tap, new question, end of a walkthrough) sends an `interrupt` control_request (the turn ends in ~20 ms with an `error_during_execution` result, turned into `CancellationError`); after 4 s, or 75 s with no output at all (watchdog), the process is restarted. ScreenCaptureKit calls hang when replayd crashes: they go through `Deadline.run` (6 s). A SpeechAnalyzer whose results end mid-session calls `onDied` → `restartListener`. The notch's ↻ (`resetEverything`) starts everything over without quitting. Failed questions speak `SpokenError.line` (usage limit with reset time from `rate_limit_event`, not signed in, offline…).
- Thinking is disabled for both Claude Code sessions (`alwaysThinkingEnabled:false`, `MAX_THINKING_TOKENS=0`) for latency.

## Testing
- Helpers: `tools/test-helpers.sh` (also in CI; it runs `tools/tests/run-web-tests.mjs`, which loads `tools/tests/*.html` in headless Chrome, e.g. helper-layout.html: many helpers at once, no overlaps; helper-reports.html: waiting at the edge, report/release, spaced sounds; helper-smooth.html: nothing visible moves while `busy` is false, since the app then runs at 10 fps; `--screen` also runs `Poinky --helper-screen-test`, which shows fake helpers through the real overlay, logs whether it stays up and each helper's phase (`SB.helperPhases()`), pretends you're busy for a while (`POINKY_TEST_BUSY`) so reports must wait, logs frame timing each second (`SB.helperStats()`), and saves snapshots of what WebKit drew (each snapshot stalls drawing for 60–140 ms, so judge smoothness with `POINKY_TEST_SHOTS=0`: a steady 60 fps on a 60 Hz display); it skips itself while the screen is locked, since WebKit doesn't animate then) tests the parser against the recorded runs in `tools/helper-runs/`, runs `Poinky --helper-talk-test` (phrases, status lines, talker tags), runs a second on-screen pass with `POINKY_TEST_TALK=1` (points the test cursor at helpers and talks to them), then runs `Poinky --helper-test <out> <dir> <task>…` with `POINKY_HELPER_CMD=tools/fake-helper.py` (replays a run, `fixture:<name>` in the task picks it, `POINKY_FAKE_SPEED`) to check the waiting line, follow-ups, stop, crashes and errors without tokens. `--live` adds one real Claude Code helper. New recordings: copy an agent's `.jsonl` log into `tools/helper-runs/` (remove personal paths).

No test target. Logic is verified with small throwaway `swiftc` harnesses that compile the relevant source files (parsers, placement, snapping, audio), plus browser-pane tests of `web/` pages with a mocked `window.webkit`. Live model behavior is checked with Python harnesses that drive `claude -p` with the real prompts.

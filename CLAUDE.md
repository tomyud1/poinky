# Poinky

A macOS menu bar app: hold ⌃⌥ and talk to Claude about what's on your screen (or ⌃⌥Space for a hands-free call), and it answers out loud while marking the screen and sketching explanations on a "paper" with a yellow pen (2D lessons) or narrated 3D models. Inspired by the HeyClicky "real-time graphics" demo.

## Where it's going (read docs/VISION.md before agent or UI work)
Poinky is meant to become the main way people use Claude Code: agents that live on the screen instead of in their own window. The main agent (the buddy at your cursor) answers instantly and hands longer work to **helpers**: smaller colored cursors that bud off the main cursor, take a task, work at the edge of the screen while showing short progress lines, then celebrate, fly back, and the main agent speaks their summary. Each helper is a real Claude Code session (`AgentManager`), so it must stay as capable as the terminal; users care about progress and summaries more than diffs. The design bar is Apple-level motion and sound (springs, one shared timing family, sounds in one key and panned to where they come from, Reduced Motion, color plus a second cue). The phased plan, with tests for each phase, is in `docs/VISION.md`. The prioritized work list after that (reliability, speed, memory, context, install, trust), written so any agent can pick up an item, is `docs/ROADMAP.md`: update an item's status when you start or finish it. The main agent never does long work itself.

## Build & run
- `./build.sh` builds `build/Poinky.app` (Swift Package, macOS 26+, no Xcode project). Then `open build/Poinky.app`.
- Restart after a rebuild: `pkill -f "Poinky.app/Contents/MacOS/Poinky"; open build/Poinky.app`. **Ask the user before restarting** if they might be mid-call.
- Signing: `build.sh` signs with your Apple Development cert if present, else the local "Poinky Local Signing" certificate (login keychain; created by `build.sh` on first run via `/usr/bin/openssl` + `security import`; the old "ScreenBuddy Local Signing" is still honored) so macOS keeps Microphone / Screen Recording / Accessibility permissions across rebuilds. Ad-hoc signing would reset them every build. `POINKY_KEYCHAIN=/path` signs/creates in another keychain (for testing); `POINKY_ADHOC=1` skips certificates (CI). Signing has a timeout (`POINKY_SIGN_TIMEOUT`, 120 s) and falls back to ad hoc, because on a headless Mac `codesign` with a new keychain key waits forever for a "allow access" dialog.
- Installer: `install.sh` (curl | bash; also `--no-voice`, `--uninstall [--purge]`) checks macOS/CLT/SDK ≥ 26, offers Claude Code, clones to `~/Library/Application Support/Poinky/source`, runs `build.sh` (log in `install.log`), runs `phonon/install.sh`, copies the app to /Applications.
- Local voice: Phonon 31m (Gradium, Apache 2.0; replaced Kokoro). `phonon/install.sh` installs it into `~/Library/Application Support/Poinky/phonon` (installs `uv` into `Poinky/bin` if missing; uv-managed Python only (`--python-preference only-managed`); pinned `ptts==0.6.0`; model + 25 catalog voices from Hugging Face at pinned revisions, each file verified by SHA-256; ends by making the helper speak; writes `installed.json`; removes the old `Poinky/kokoro`). `POINKY_PROGRESS=1` adds `@progress <0-1> <step>` lines, which `PhononInstaller` (Settings → Voice → Install, and automatic when `Poinky/kokoro` exists) shows. Test it as a new user with `env -i HOME=/tmp/x PATH=/usr/bin:/bin:/usr/sbin:/sbin bash phonon/install.sh`.
- Settings: `~/Library/Application Support/Poinky/config.json` (also editable from the Settings window).
- In-app updates (`Updater.swift`, Settings → General → Updates, green arrow in the notch): build.sh stamps `PoinkyCommit` / `PoinkyCommitDate` / `PoinkyDirty` / `PoinkySource` into Info.plist; the app fetches the branch its source folder follows, runs build.sh there (log `Poinky/update.log`), and restarts only when you click Restart (an app in /Applications gets `Poinky.app.new`, swapped in after it quits). The installer's `Poinky/source` is reset to GitHub's version; any other folder (a developer checkout) is only fast-forwarded and never with uncommitted changes. Checks 90 s after launch and every 6 h (`checkForUpdates`).

## Architecture (Sources/Poinky)
- `CallController` runs a session in one of two modes: hold-to-talk (`PushToTalk` polls the modifier keys; the mic opens only while held; release → `SpeechListener.finishUtterance()`) or a hands-free call (mic always on, silence ends a question). The loop: listen → screenshot → **talker** (fast model, short spoken answer + quick screen marks) and **teacher** (stronger model, narrated `<lesson>` sketches or `<scene3d>` models) → speak + draw. Handles interrupts, follow-ups, placement, window anchoring.
- `Brain` protocol: `ClaudeCodeBrain` (persistent `claude -p` stream-json session, uses the subscription; `findClaude`: config path, usual install spots, a login shell, then `bundledClaude`: the copy inside the Claude desktop app or the Cursor / VS Code extension, newest first) and `APIBrain` (Messages API). Parsers: `TalkParser` (`<say>/<visual>/<draw>`), `ArtistStream` (`<lesson>/<say>/<step>/<step3d>/<scene3d>`).
- What the voice hears: `SpokenText.normalize` (Speaker.pump, before Phonon or Apple's voice; captions and steps keep the text as written) says math, symbols, paths, file names, links, keys, dates, markdown and emoji the way a person would ("x squared plus 3x", "a dot P Y", "example.com"). `SentenceSplit` (used by `TalkParser`) cuts replies into sentences: the first piece may end at a comma (not when fewer than 3 words follow before the sentence ends: "…right, Dana." stays one), a period after "e.g."/"Dr."/a list number or before a lowercase word doesn't end one. Test: `tools/test-voice.sh` (in CI); A whole sentence clearly in another language (`SpokenLanguage.foreign`, NaturalLanguage; strict) is said by Apple's best voice for that language, since Phonon only speaks English; in a mixed sentence the part in another script (`SpokenLanguage.runs`: Hebrew, Arabic, Cyrillic, CJK…) is (`Speaker.segments`: parts after the first have no caption, and only the last part's end lets the next caption show). `POINKY_SPEECH_LOG=file` logs caption ⇥ spoken text for each sentence. For Phonon a short number at the very end is spelled out (`SpokenText.phononEnding`: digits before the end of the text came out as "7 point", "58 dawn"). Apple's voice for another script is warmed with a silent utterance on the same synthesizer (`Speaker.prepareVoices`: on each streamed delta, each queued sentence, and at session start for macOS's preferred languages; cold ≈0.85 s for Hebrew); where voices hand over mid-sentence only `Speaker.joinTail` of silence is kept (Phonon's `"tail"` request field, Apple's trailing silence held back). `SentencePause.after` adds 0.3 s after a heading/colon and 0.22 s after a list item, inside the sentence's closing silent buffer (so captions/steps stay in sync). `POINKY_SPEECH_WAV=file.f32` records what's played, with any wait for audio as silence, to measure pauses and transcribe.
- Audio: `AudioIO` (one AVAudioEngine; voice processing for echo cancellation), `SpeechListener` (SpeechAnalyzer; ends on real silence via `VoiceActivity`; SpeechTranscriber only updates about once per second of audio, so for holds a DictationTranscriber runs in the same analyzer just for the live caption (`shownText`; `POINKY_LIVE_CAPTIONS=0` turns it off) and is the fallback when the main final is empty; a hands-free question is finalized before it's sent (results can't be dropped by time: a new segment starts where the last final ended), and results about audio with no voice in it are dropped (`MicFeeder.hadVoice`)), `Speaker` (sentence queue, tagged lines so drawing steps start with their sentence; a lesson line isn't queued behind the one before it until that one is heard, and a 3D step calls `holdNext` (`CallController.stepDwell` 2.2 s from the step, `stepBreath` 0.4 s after its sentence) so the next sentence waits at the gate; Phonon audio is streamed chunk by chunk after a 0.1 s safety buffer, and a 10 ms silent buffer closes each sentence: it flushes the resampler and moves the captions on), `PhononVoice` (`phonon_server.py` over stdin/stdout: `{"id","text","voice","speed"}` in, `{"id","bytes"}`+float32 chunks then `{"id","end"}` out, `{"cancel": id}` drops everything up to that id mid-sentence; CPU q8_0 weights on performance cores (max 4 threads, faster than also using efficiency cores), QoS userInteractive; speed is a multiplier mapped onto Phonon's `duration_delta` (reliable only 0.86–1.24×); `SilenceTrimmer` cuts the ~120 ms of silence before and ~600 ms after every sentence, with a threshold set from each sentence's own noise floor, since some voices have room tone near -65 dB and a soft "f" is near -55 dB).
- First run (`Welcome.swift`): a 5-page tour (hello, permissions one at a time with plain reasons, Claude Code installed/signed in via `claude auth status` (JSON `loggedIn`; anything unreadable is "couldn't tell", never "signed out") with one-button fixes that open Terminal, a first question about a sample problem drawn in the window (`ScreenCapture.tourWindowNumber` keeps it in the screenshot), tips: tap to stop, ⌃⌥T, the notch). Opens for a new install (no config.json) or one left halfway (`welcome.json`; quitting keeps it pending, the close button or Done ends it); replay from Settings → General or the menu. Settings → General → "Why isn't it working?" (`SetupCheckSection`) runs the same checks (permissions, Claude Code, hold keys, voice) with a fix button on each. `Poinky --welcome-shot <dir>` renders every page and state to PNGs (`POINKY_SHOT_DARK=1` for dark); `--welcome` forces it open. The same window opens on one page with Done (`offerFix`, `fixing`) instead of an alert when a session lacks permissions, or when a question fails because Claude Code is missing / not signed in (`SpokenError.notSignedIn` / `notInstalled`); test with `FAKE_CLAUDE_MODE=signedout` (the fake also answers `--version` and `auth status`). `POINKY_SUPPORT_DIR` points all settings/memory at a scratch folder (use it for shots and launches).
- First-run moments (`FirstRun.swift`, words in `FirstRunWords.swift`, no model): the tour's Done/Skip (`WelcomeModel.onTourDone`) → the buddy says hello at the cursor (name from user.md if clearly written, e.g. "My name is…"; Phonon if installed, else Apple's voice; captions per sentence; if the tour's first question left a session open it's said in that session via `sayInSession`); the first session end ever (`AppConfig.homeShown`; a config.json without the key counts as shown) → "I live here": `SB.homeGo` flies the buddy under the notch (or the menu bar icon without a notch; Reduced Motion fades instead), `NotchModel.beckon` opens the notch a little with a blue glow, it speaks, `SB.homeEnd` tucks it in. Both wait until you're free (idle, not typing 3 s, unlocked, no tour / type box / video; "I live here" also until some input in the last 90 s, since a session can end by itself after 15 idle minutes) and stop on a session start, a tap, a key press or Start Fresh. Tests: `tools/tests/buddy-home.html`; `--firstrun-hello [secs]` plays the hello (after an `--ask`, it's said in the open session); `POINKY_FIRSTRUN_SHOT=<dir>` saves the overlay, the notch and `SB.homeState()`; walk it with `--ask … --end-after 9` (seed `"homeShown": false` if you seed config.json).
- Home: `NotchHome` (SwiftUI in a panel above the overlay, centered on the notch; idle it's exactly the notch's size so it's invisible; hover opens controls). The menu bar item is hidden unless `menuBarIcon` is on or no screen has a notch. The hover panel's info line also shows the next reminder within a day (`Reminders.nextLine`); `Poinky --notch-shot out.png` renders the opened panel. Sounds: `Earcons` (synthesized; played through `AudioIO`'s own player node during a session).
- Screen: `ScreenCapture` (ScreenCaptureKit; image size kept ≤1568px / 1.15MP so Claude's coordinates are 1:1), `MarkSnapper` (Vision OCR lines + words; small print that Vision cuts short or misses is read again from a thin strip (`rereadCutLines`, `TextIndex.lines(inStrip:)`); marks with `"find"`/`"to"` are placed on that text (a match far from the mark's x,y is looked for around the mark first), others are fitted to the lines / icon they're around (`nudgeTarget`); `fit` uses the real ink (`InkMap`: OCR's boxes clip handwriting and roots): circles become ellipses (`rx`/`ry`) around the whole target, boxes include a checkbox/number before them, underlines sit in the gap under the letters, brackets left of where the lines start, arrows end just outside with the tail moved off the target / into the screen, and at the screen's edge a mark becomes a highlight; label spots `lx`/`ly`/`la` cover the least text and picture), `Placement` (the paper and 3D cards: `Room` = subjects (your marks, the talker's marks, the brief's "around x,y" / "x1,y1 to x2,y2" (`region(inBrief:)`), the teacher's first-step screen marks; a new lesson's paper opens with its first step), cursor, other cards, OCR text density; never covers a subject while a 360×240 pt paper fits beside it; the paper grows only inside its band (`lo`/`hi`); an open paper over the next question's marks moves aside (`SB.lessonPlace`; one you dragged stays); captions), `WindowTracker` (drawings follow/hide with their window).
- 3D step notes: `<step3d id note="…">` (the teacher writes 2–6 words; missing → `CallController.shortNote` of its sentence, once per sentence; a fix with no sentence adds none) → `SB.run3d(id, code, note)` adds a line to the model card's notes column (`addNote`: the card grows on the side with room, away from the photo, so the 3D view keeps its size; no room → over its left edge) and sends `{sbRun, note: i}`. The kit saves each step's camera goal when the next step starts (`saveView`) and its temp labels (`noteTemps`); clicking a note sends `{sbRevisit: i}` → `kit.revisit(i)` (camera back, temp labels again, its part labels flash); the next step first returns to the lesson's view. Test: `tools/tests/kit-notes.html`. Clicking a part (`kit.pick`) lights it up and shows its label, or its `name:` made readable (codes like 'lv' show nothing; glass and cut-away halves are clicked through), and the talker's scene line says which part you clicked for 2 min (`{sbPicked}` → `{kind:'picked'}` → `Overlay.sceneDescription`); with Reduce Motion the kit drops camera sway/swoop/turntable and drop-in bounces (spins and flows still run). A cut along an axis seen edge-on turns the camera to the cut face. Resting on a part shows its name; zoomed in, labels of parts out of the picture hide and the step's own labels pull the camera back. A still model stops redrawing (the sway settles 20 s after the last step or touch, `swayFor`; `kit.renders()`). Tests: `kit-pick.html`, `kit-motion.html`, `kit-zoom.html`, `kit-idle.html`; `eval3d/` replays real teacher replies (`try.py` for one snippet).
- Asking about a clicked part: the click sends `{sbPicked, part}` (shown name, which falls back to the part's first label after `clearLabels`, plus its code name); `Overlay.freshPick` (2 min, once) + `PartQuestion.isAbout` route "what's this?" to the teacher with `PartQuestion.brief` (talker gets `talkerLine`: only names the part). That job's `<step3d>` on the model run as an **aside** (`kit.run(code, note, {aside:true})`, one note, square yellow badge): `kit.clicked()`, closer `focus`; `maybeEndAside` sends `SB.end3dAside` `asideLinger` (2 s) after the teacher is done and its lines were heard → `kit.endAside()`: lesson's view back, cuts/x-rays/explode/isolate from the aside undone, its parts, motions and labels fade. Its note replays the aside code; the lesson's next noted step ends an open aside. Double-click a part = a closer look (aside with no code); Esc or a click on empty space goes back. Test: `tools/tests/kit-ask.html`.
- Overlay: `Overlay.swift` + `web/overlay.html` (annotations, cards, captions), `web/lesson.js` (paper + pen engine), `web/buddy.js` (cursor buddy + caption bubble; sounds are native `Earcons`; it wraps `SB.caption`/`SB.apply`), `web/kit.js` (3D kit over three.js r160 in `vendor/`). Cards run in sandboxed iframes with no network.
- Paper lessons (`web/lesson.js`): besides text/box/arrow/line/dot, the teacher has `math` (TeX-like: `\\frac`, `^`, `_`, `\\sqrt`, Greek; a JSON `\f`/`\t`/`\b` that ate a backslash is put back), `graph` + `plot` (`fn` is parsed by `compileFn`, a math-only parser: never eval model text in the overlay) + `point`; a graph with `categories` (names under the axis, tilted when long, no numbers) takes `bars` / `plot` with `values` and points by name (`xOf`; test `lesson-charts.html`). Text has a paper-colored halo, chemical formulas get subscripts, labels avoid arrows/curves, too-wide text shrinks. The digit 1 comes from Chalkboard SE (`@font-face` `PoinkyHand`), since Noteworthy's 1 looks like l. The paper's Save button renders it to a 2× PNG (`paperPicture`) → `{kind:'saveLesson'}` → `LessonSaver` (Desktop, else Pictures/Poinky; `POINKY_LESSON_DIR` for tests) → `SB.lessonSaved`. `table` + `row` draw hand-drawn tables. Each `lessonStep` is a numbered step (`data-step` on its groups); nothing already drawn ever fades while another step draws (earlier steps used to dim, which people found confusing; the test fails if any drawn group's opacity drops); clicking a past step re-inks it (`replayStep`, posts `{kind:'lessonReplay'}`, which the app ignores for now). Ops from the model are cleaned first (`opsOf`: one op or nested lists become a list; `clean`: numbers as strings, missing positions go below what's drawn, bad ranges/steps fixed); an interrupt or a new lesson rejects the running tween (`CANCELLED`), so the op stops there instead of drawing on (test `lesson-robust.html`). Check by eye: `node tools/lesson-shots.mjs reply.txt outdir [--bg dark] [--size 1280x720]` replays a teacher reply through the real overlay (`tools/lesson-player.html`) and saves a picture per spoken line plus `saved.png`; test: `tools/tests/lesson-paper.html` (`node tools/tests/run-web-tests.mjs lesson`). Chalkboard: `openPaper` measures the screenshot under the paper (`PaperLook.brightness`, dark below 0.38) and passes `look:'chalk'` (setting `paperLook` auto/paper/chalkboard); lesson.js swaps its palette (`useLook`; `legible` turns dark model colors chalk-white; screen marks keep `PEN_INK`) and adds a grain tile that the PNG gets too (lesson-player: `?bg=dark` or `?look=`). Notebook: every paper of a session (`session: callID`) is kept as SVG (`keepPage` after each drawing, before a wipe/close); "Save all N" → `{kind:'saveNotebook', pages}` → `LessonSaver.saveNotebook` (one PDF, a page per paper with its title). Voice: the talker's `<save-lesson/>` / `<save-lesson pages="all"/>` → `SB.saveLesson(all)` → `onLessonSaved` → `lessonSaved` says where, after what's being said.
- Identity and history: `Identity` (identity.md = Poinky's personality, user.md = "About me"; user-editable, always in the talker/guide/doer prompts), `DailyNotes` (a session's 1–4 lines written by `writeDailyNote` when it ends; yesterday's and today's in the prompt, all of them searchable by `<recall>`), `Memory` (facts; the oldest go to memory-archive.md past 80). Poinky edits identity.md / user.md only in their "## Learned over time" part (`Identity.learn` / `unlearn`), from `<remember about="poinky|user">` / `<forget about=…>` and the note writer's `ABOUT: fact | "their words"` lines. user.md gets only what the user said about themselves (`UserFacts`: an ABOUT line's quote must be in what the user said, and not already in memory.md; a talker's about-user fact must share a word with what they just said), never the app in use, a page they viewed or a name read off the screen. See docs/ROADMAP.md item 3.
- Talker extras (parsed in `TalkParser.finish`): `<remember>`/`<forget>` → `Memory` (memory.md, added to talker + guide system prompts), `<set>{…}</set>` → a whitelist of safe settings (`applyVoiceSettings`), `<agent title dir>task</agent>` → `AgentManager`, `<end/>` → end the session after speaking. Finished agents queue in `agentReports` (with their ids) and are spoken when you're free (`deliverReports`: not while holding the keys or Claude talks, not within 2 s of a key press (`secondsSinceTyping`), not while the screen is locked (`screenLocked`); idle starts a quiet session) or added to the next question. `startReporting` sends `SB.helperReport` (the helpers fly to the buddy) and marks them heard in the notch; `releaseReports` (`SB.helperRelease`, they merge) runs when the speech ends, a new question starts, or the session ends. `NotchModel.reports` keeps the last 12 (dots for unheard ones, the last three in the hover panel).
- Offers (`Offer.swift`): the talker can end "Want me to swap it in?" with the action ready in `<offer say="…">…</offer>`; `TalkParser` keeps it aside (`TalkEvents.offer`, nothing in it is said or run), `handle` stores it as `pendingOffer`, and `heard(utterance:)` → `takeOffer`: a clear yes (`OfferReply.classify`, English + Hebrew, short answers only) says the line and runs it through `handle` with no model call; a clear no drops it; anything else goes to the talker. Only do/guide/visual/agent/remind/set/tell may wait (`PendingOffer.allowed`); lookup and proactive replies can't offer; it lapses after 60 s or when the front app, window or selection changed (`check`). Test: `tools/test-talker.sh`.
- Study sessions (`StudySession.swift` state, words, intents, `StudyStream`/`StudyBrief`; `CallController+Study.swift` the flow; `StudySource.swift` PDF pages + photo cleanup (Vision document segmentation, perspective, `CIDocumentEnhancer`); `StudyPDF.swift`): "let's do this homework together" (`StudyIntent.start`, or the talker's `<study q="2"/>`) → `studyRead`: a study teacher (artist prompt + `study-prompt.md`, artist model, effort medium, `POINKY_STUDY_MODEL`/`_EFFORT`) gets "STUDY: present" with the screenshot and the question's PDF pages (`questionPages`, PDFKit text search) and writes `<question>{json}</question>` (statement, givens, figure, parts with `say`) then a lesson without the parts; a hidden solver (`study-solver-prompt.md`, Opus, effort high) solves every part at once (`studySolve`) and hints ≥2 / checks / solutions wait for it (`solverWait`). Part presentation, "try it", next/skip/stop/resume, PDF and include choices are code (`studyPresentPart`, `StudyWords` EN/HE); the teacher gets hint/solve/check/fix/fix-hint/ask, all through `runArtist` with a `StudyJob` (own brain, extra images, a tap that pulls out `<question>`, `<verdict result line>`, `<pass/>`). State: `Poinky/study/<sheet id>/state.json` (0600) after every change, plus each part's papers (lesson.js `SB.studyTag`/`SB.studyPictures`, kept after each turn) and cleaned photos; the PDF next to the sheet (`POINKY_LESSON_DIR` for tests), Creator "Poinky study", never over a file Poinky didn't make. Photos: `StudySession.shared.checkWork(image:)` (the iPhone capture's entry point), `--study-photo <file>` among `--ask`s. Hooks in shared files are marked "Study" / "CallController+Study.swift". Tests: `tools/test-study.py` (fake brain: `FAKE_STUDY_SCRIPT`, `POINKY_STUDY_DOCUMENT`), `Poinky --study-eval <out> <sheet> <en|he> present:1 hint check:photo.jpg solve …` (real models, no screen), `Poinky --study-pdf state.json out.pdf`; samples in `tools/study/` (`make-work.py` makes the handwriting photos).
- Reminders (`Reminders.swift`): `<remind at="YYYY-MM-DD HH:MM" every=… agent=… dir=…>` / `<remind-cancel>`; `reminders.json`; `checkReminders` every 20 s (`POINKY_REMINDER_TICK`) and on wake; due ones are said with `sayWhenFree` under the report rules, or start their helper. Helper reports (`ask(proactive: true)`) can only speak and mark (`lookupReply = proactive`).
- What's in front (`AppContext.swift`): with each question, read alongside the screenshot, the front app's window title, open document, web page (http(s), secret-looking query parts removed) and selected text (never secure fields or excluded apps) go into the talker's message (`frontContext.lines`; setting `frontAppContext`). `Poinky --read-context out.txt` shows what it sees. Poinky is for every kind of user (students with lecture PDFs, writers…), not only developers: test with those apps too.
- Receipts (`Receipts.swift`, `ReceiptsWindow.swift`): each question (`addReceipt` in `ask`; one per walkthrough in `guideReceipt`, counting steps) records what went out: a 640 px thumbnail, `frontContext.lines`, the files in the instructions by name + size (`Receipts.sessionParts`, set in `BrainFactory.make`), lookups, the teacher getting the screenshot, role/model, the whole text message. `receipts/` in the support folder (0600, last 20; `POINKY_RECEIPTS_DIR`), nothing with the `receipts` setting off (turning it off clears). The notch's hover panel shows the last one as one quiet "🔒 What I saw" line (only when something was sent in the last 12 h) → the window; also Settings → Privacy. `Overlay.glance()` (`SB.glance`: a glint on the buddy, a fade with Reduced Motion, a faint screen-edge glow while it's hidden) right after every capture sent to Claude. Test: `tools/receipts-test/run.sh`; `Poinky --receipts-shot out.png`, `--settings-shot out.png privacy`.
- Looking things up (`Recall.swift`, `WebSearcher.swift`): the talker's `<recall>words</recall>` and `<search>query</search>`. `CallController.ask` speaks the short line, runs `lookUp` (recall: `Recall.find` over `ConversationLog` + `PastHelper.list` + `ClaudeSessions`, no model; search: `WebSearcher`, its own `claude -p` with `--tools WebSearch,WebFetch` + `--allowedTools` and nothing else, in `Poinky/web-search`, 30 s timeout (it says "Still looking." after 10 s; searches take ~10–20 s, WebFetch at most one page), started as soon as the reply contains `<search`), then sends the results as a text-only follow-up turn (`BrainQuestion(snapshot: nil)`). While `lookupReply` is set, `handle` keeps only `<say>/<draw>/<visual>` (`TalkEvents.onlySpeech`), so web pages and old transcripts can't start helpers, click, change settings, remember, or look up again. `ConversationLog`: `conversations/YYYY-MM-DD.jsonl` (0600; you, poinky, front app, note), written by `logExchange` (setting `conversationLog`); the first question of a session gets the last 3 exchanges if they're under 3 h old (`carriedOver`). `ClaudeSessions` reads only the last 96 KB of each `~/.claude/projects/*/*.jsonl` changed in 30 days (custom-title / ai-title / last-prompt / cwd / gitBranch), skipping Poinky's own helpers; `<agent resume="cc-…">` continues one as a helper with `--resume` + `--fork-session` in its own folder (no worktree; helper notes go in the message, since a resumed session keeps its system prompt). The talker's instructions for both are added in code (`LookUp.promptSection`), depending on the settings. `POINKY_CONVERSATION_DIR` / `POINKY_CLAUDE_PROJECTS` point them elsewhere for tests.
- Helpers (background agents, `AgentManager`): each is `claude -p --input-format stream-json` in the project folder, with a name from `AgentManager.names` (Mint, Coral, Violet, Amber, Rose, Sky; no Blue, since the main buddy is blue). Input stays open so `send(id:text:)` can add follow-ups: Claude Code folds a message that arrives mid-turn into the current turn (one result), and one that arrives after a result starts a new turn. ## Hard-won gotchas
- Voice processing: create the engine's output side (`outputNode`, `mainMixerNode`) **before** `setVoiceProcessingEnabled(true)`, then connect mixer→output with the output node's format, or the engine fails with -10875. Mic channel 0 is the cleaned voice (9 channels come back).
- `@State` doesn't compile with CommandLineTools (its macro plugin is missing): keep SwiftUI view state in an `ObservableObject` (e.g. `NotchModel.hoverButton`).
- The talker may write several `<say>` blocks; `TalkParser` speaks all of them. `JSONRepair` also tries dropping a stray `}`.
- Hold-to-talk audio: playback runs in an engine that never touches `inputNode` (touching it would open the mic); the mic is a separate engine started per hold. `MicRelay` keeps audio that arrives before the speech engine is ready.
- SpeechAnalyzer: `finalize(through: nil)` settles a hold in ~0.2 s (with a time it can hang). Don't drop results by timestamp after a finalize: the final for new speech can start slightly before the press.
- Vision OCR: pin `VNRecognizeTextRequestRevision3`; the newest revision took ~30 s per screenshot on macOS 27.
- WKWebView: the overlay loads from the bundle with `loadFileURL`; three.js and the kit are passed as text (`web/libs.js`, generated by build.sh) because sandboxed frames can't load files.
- App Nap: with no session running (no audio), macOS naps Poinky and WebKit pauses the overlay's animations, so helpers froze mid-flight. `Overlay` holds a `ProcessInfo.beginActivity` while it's on screen (`keepAwake`).
- Phonon: after any pause over ~0.1 s the first chunk takes ~20 ms instead of ~5 (the CPU clocks down); a warm-up ping while the reply streams in only saved ~3 ms, so there isn't one. The first sentence after the helper starts, and the first with a new voice, are also ~15 ms slower.
- Phonon's audio chunks grow (80 ms, 80 ms, 240 ms, 480 ms…), arriving ~6 ms apart at first, so the 0.1 s buffer before playing costs a few ms and protects against main-thread stalls.
- Audio device changes (AirPods connecting or hopping between iPhone and Mac, and especially AirPods going into headset mode with a different sample rate when a mic opens) stop the AVAudioEngine with `AVAudioEngineConfigurationChange`; everything scheduled then reports "played" at once in silence. `AudioIO` rebuilds the engine (`restartIfStopped`, 0.3 s after the last change, retries while Bluetooth connects) and calls `onRestart`; `Speaker` notices the first completion from a stopped engine (`lostDevice`), keeps its place (`keepPlace`: the cut sentence and anything scheduled go back to the front of the queue) and replays from there without repeating captions or steps. Simulate it by changing the speakers' nominal sample rate (48000 → 44100) mid-sentence; a plain device switch at the same rate doesn't stop the engine.
- Never wait on a Claude reply or a system call without a way out. `ClaudeCodeBrain` answers one question at a time, so a stuck turn used to freeze every later question: `Brain.cancelCurrent()` (called on interrupt, tap, new question, end of a walkthrough) sends an `interrupt` control_request (the turn ends in ~20 ms with an `error_during_execution` result, turned into `CancellationError`); after 4 s, or 75 s with no output at all (watchdog), the process is restarted. Never write to a child's stdin on the main thread: a message with a screenshot is bigger than a pipe holds, and a Claude Code that isn't reading (hung while starting) froze the whole app, watchdog included (`ClaudeCodeBrain.send`: a writer queue per process; `FAKE_CLAUDE_MODE=stuffed`). ScreenCaptureKit calls hang when replayd crashes: they go through `Deadline.run` (6 s). A SpeechAnalyzer whose results end mid-session calls `onDied` → `restartListener`. Start Fresh (`resetEverything`: Settings → General → "Why isn't it working?", the ✨ menu, or saying/typing just "start fresh" (`isStartFresh`); no longer in the notch) starts everything over without quitting. `Timeline` (`Poinky/timeline/YYYY-MM-DD.jsonl`, 7 days, no words) logs states, keys, capture ms, first token, first sound (`Timeline.latency`), cancels, restarts and timeouts; `app.start` / `app.quit` (a session with no `session.end` before the next `app.start` was killed, crashed or lost power); `checkStuck` (its own 2 s timer, so a session stuck in `.starting` is caught too) resets after `stuckAfter` (thinking 150 s, starting 300 s) and logs every flag. Settings → Advanced → Diagnostics shows the median wait and copies the last 200 lines. Long sessions: when the talker's conversation reaches `talkerRotateTokens` (70k, from Claude Code's `usage`: `Brain.contextTokens`; `POINKY_ROTATE_TOKENS`) or after `talkerRotateAfter` (24, `POINKY_ROTATE_AFTER`) questions a fresh talker is warmed up (`prepareFreshTalker`) and takes over at the next question (`swapTalkerIfReady`) with `recapLines`: the running `SessionSummary` (after each answer the talker's model folds the exchange into ≤1,200 characters in its own small session, in the background; nothing waits for it; 3 failures in a row and it stops for the session; also given to `writeDailyNote`) plus the last 5 exchanges; after a swap the summary's key facts (`keyFacts`: the user's words pinned by `lastingFacts` (no model, e.g. "my exam is on Thursday…"), then Facts/Goal/Open, ≤400 characters) go first in each message, again when they change (`sendOnce`) (live check: `tools/eval-talker/continuity.py`), since every screenshot stays in a `claude -p` conversation (~2,500 tokens each); `fake-claude.py` answers the summarizer (`FAKE_SUMMARY_MODE` hang/fail) and reports growing usage (`FAKE_TOKENS_PER_TURN`); `sendOnce` sends the earlier-helpers and commands lists only when they change. Failed questions speak `SpokenError.line` (usage limit with reset time from `rate_limit_event`, not signed in, offline…).
- Thinking is disabled for both Claude Code sessions (`alwaysThinkingEnabled:false`, `MAX_THINKING_TOKENS=0`) for latency. Claude Code 2.1.3xx ignores both for Haiku 5.5 (it thinks it can't turn thinking off) and Haiku then thought 1–4 s before its first word, so on Automatic effort `ClaudeCodeBrain` also sets `CLAUDE_CODE_EXTRA_BODY` = `noThinkingBody(for:)` (Haiku: thinking `disabled`; Sonnet: `between_tools`, which the API asks for instead (the doer thought ~1.4 s before its first act); other models and any chosen effort unchanged; plus empty `context_management`, since Claude Code's `clear_thinking` edit requires thinking); a 400 about it retries the question once without it and turns it off for that model (`retryWithThinking`). Helpers don't use `ClaudeCodeBrain`, so they keep thinking. Without thinking Haiku drifts from the reply format, so every talker message ends with `formatReminder`, and checking their work ("did I get number 2 right?", or "is this right?" on selected math) starts the teacher's check (`TalkerRoute`).

New recordings: copy an agent's `.jsonl` log into `tools/helper-runs/` (remove personal paths).
